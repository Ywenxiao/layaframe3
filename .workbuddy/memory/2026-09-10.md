## 本项目的关键坑（下次直接照做）

1. **资源路径不带 `assets/` 前缀**：loader 根就是 `assets/`，`assets/cdn/map/1.png` 要写成 `cdn/map/1.png`。
2. **`Laya.PrimitiveMesh.createPlane` 生成的就是 XZ 水平面**（顶点 y=0、法线 (0,1,0)），
   不要再绕 X 转 -90°，否则地块会立起来。UV：U 随 +X 增，V 随 +Z 增；3D 管线上 v=0 是贴图顶部，
   所以贴图上下方向是正确的。
3. **相机 forward = -Z，右手系**（已核对 laya.core 的 `Matrix3x3.lookAt`：s = f × up，Z 轴 = eye-target）。
   推论：俯视时只要屏幕右是 +X，屏幕上方必然是 -Z。
   所以「底行」要放在 **+Z**，`z = offsetZ - row * tileSize`。
4. **`Laya.Scene` 已内置 `scene3D` 访问器**，IDE 风格 generated 基类里再 `declare scene3D` 会报 TS2610。
5. **相机高度要算，不能拍脑袋**：8×9×512 = 4096×4608。fov 60、设计宽高比 0.562 时，
   y=2500 会横向溢出约 2.5 倍；y=7600 才能完整容纳（near/far 距离比 1.036 ≈ 3.6% 透视）。
   farPlane 必须 > 最远角点距离（约 8356），已设 12000。

## 贴图加载：为什么 `Laya.Loader.TEXTURE2D` 返回 null（重要）

Texture2D 资源由 IDE 导入生成，两处产物：
- `assets/xxx.png.meta` —— `{uuid, importer:{textureType:2}}`（textureType 默认值来自 `settings/EditorSettings.json`）
- `library/<uuid前2位>/<uuid>.json` —— `{type:2, sRGB, wrapMode, filterMode, mipmap, pma, hdrEncodeFormat, files[]}`
  这份就是运行时构造 Texture2D 需要的 meta。

**`Texture2DLoader` 拿不到这份 meta 就会 resolve 成 null（不抛错、不 404）。**
资源要进「运行时资源索引」（构建产物 `fileconfig.json` 的 files + config）才拿得到，条件是三者之一：
1. 放在 `assets/resources/` 下；
2. 被已打包的场景/预制体引用（依赖分析带入）；
3. 列在 `settings/BuildSettings.json` 的 `alwaysIncluded`（当前是 `[]`）。

`assets/cdn/map/` 三条都不满足 → 带 `TEXTURE2D` 加载恒为 null。

**写法**：不带类型加载走 2D 图片通道，返回 `Laya.Texture`，取 `.bitmap` 就是底层 Texture2D，
正好是 `material.albedoTexture`（要求 `BaseTexture`）需要的。

项目约定（`src/core/apk.ts`）：`apk.resCDN()` = `"cdn/"`（CDN 远程图，走 2D/URL 加载），
`apk.resLocal()` = `"resources/"`（打进包，可走资源索引）。

实测探针结果（同一运行时）：
```
cdn/map/1.png  无类型      -> Texture   OK
cdn/map/1.png  TEXTURE2D   -> null      FAIL
res://<uuid>   TEXTURE2D   -> null      FAIL   (换 uuid 也没用)
resources/apk/bg.jpg TEXTURE2D -> Texture2D  OK  (对照组)
```

**发布构建注意**：`cdn/map` 不在索引里，构建时物理文件也不会拷进 `release/`
（现有 `release/web/fileconfig.json` 只有 internal/UI、resources/apk、resources/common）。
真要上包，得把切片移到 `assets/resources/map/` 或加进 `alwaysIncluded`，
否则预览能跑、出包必白。
